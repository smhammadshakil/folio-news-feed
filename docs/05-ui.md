# UI behavior

Folio should read like a newspaper front, not like an admin dashboard. One type family for headlines, one for UI, a paper background, and an accent used only for links, the active source, and the primary button.

## Screens

There is one route, `/`.

### Feed

Top to bottom:

1. Sticky toolbar. Wordmark "Folio", search field, Filters button (hidden from `lg` up), "My feed" button, light/dark toggle.
2. Optional banner. Fixture mode, or one or more source failures.
3. Active filter chips, when the on-screen query is narrower than "everything."
4. Result count.
5. The grid, the skeleton, the empty state, or the full error.
6. "Load more" under the grid when another page is likely.

From the `lg` breakpoint up, `FilterPanel` is a left sidebar (280px) and the list sits in the remaining column. Below `lg`, the sidebar slot is omitted and Filters opens a Chakra `Drawer` with the same `FilterPanel` and an Apply button that closes the drawer. On desktop, checkbox changes apply immediately.

### My feed

"My feed" opens a drawer from the right.

- Title: "Your feed".
- Short line: "This is what Folio opens on. It does not change the filters in the address bar until you save."
- `PreferencesForm`.
- Primary button: "Save feed". On success, close the drawer, write `localStorage`, and if the URL has no overriding params, refetch with the new preferences.
- Ghost button: "Reset". Restores all sources, all categories, no authors, then saves that default.

Editing preferences does not live-update the grid while the drawer is open. The reader should be able to cancel by closing the drawer. Closing without Save discards the draft.

## Copy

Use these strings. Do not leave placeholder text in the UI.

| Moment | Copy |
| --- | --- |
| Search placeholder | Search headlines |
| Empty feed title | Nothing matches this feed |
| Empty feed body | Try a broader keyword, or clear the date, category, and source filters. |
| Empty action | Clear filters |
| Full error title | The feed did not load |
| Full error body | Check the connection and try again. |
| Full error action | Try again |
| Fixture banner | Showing sample articles. Add API keys and set DATA_MODE=live for today's news. |
| Source error banner | Some sources did not respond. |
| Load more | Load more |
| Loading more | Loading |
| Save feed | Save feed |
| Preferences reset | Reset |
| External link | Read story |

| `accent` | `#8f1d2c` | `#e06a78` |
| `accentFg` | `#fffaf7` | `#1c1915` |

Fonts, loaded through `@fontsource` so the Docker build does not depend on Google's CDN at runtime:

- Headlines: Newsreader.
- UI and body: Source Sans 3.

Chakra font tokens: `heading` = Newsreader, `body` = Source Sans 3.

Radius stays small (`sm` on cards and inputs). Shadows stay off. Separation comes from `line` borders. Cards are `paper` elevated only by a 1px border, with the image flush to the card edges.

## Responsive rules

Breakpoints are Chakra's defaults. The layouts that matter:

| Width | Behavior |
| --- | --- |
| base, under 768px | One column. Toolbar wraps so search is full width on the second row. Filters in a drawer. Card image is 16:9. Page padding 16px. |
| `md`, 768px and up | Still one content column. Toolbar fits on one row. |
| `lg`, 992px and up | Sidebar plus a 2-column card grid. Filters button hidden. |
| `xl`, 1280px and up | Sidebar plus a 3-column card grid. |

Check these widths during step 16: 375, 768, 1100, 1440.

Touch targets for filter checkboxes, chips, and the load-more button are at least 44px tall on base.

## Interaction details

- Search waits 300ms after the last keystroke, then updates `q` and resets `page` to 1. Pressing Enter flushes immediately.
- Changing any filter resets `page` to 1 and replaces the list. It does not append.
- "Load more" keeps the current articles on screen, fetches `page + 1`, and appends ids the list does not already have.
- The document title is `Folio` when the keyword is empty, and `Folio · {keyword}` otherwise.
- Focus outlines stay on. Do not set `outline: none` globally.
- Color mode is stored by Chakra's color-mode snippet (`class` strategy on `<html>`).

## States the page must render

| State | What the reader sees |
| --- | --- |
| First load | `FeedSkeleton`. Toolbar and filters are already usable. |
| Ready | `ResultCount`, `ArticleList`, maybe `Load more`. |
| Empty | `EmptyFeed`. No skeleton. |
| Partial | Articles plus `SourceHealth`. |
| Failed | Error title, body, and Try again. Filters remain so the reader can loosen them. |
| Loading more | Existing cards stay. The button shows "Loading" and is disabled. |
| Invalid stored preferences | Ignore the JSON, use the default feed, overwrite the bad value on the next save. Do not show a stack trace. |

## Accessibility

- The search field has a visible label "Search", not only a placeholder.
- Filter groups are `<fieldset>` elements with legends "Date", "Category", and "Source".
- Article titles are `h2`. The page has one `h1`, the visually present wordmark.
- The drawer traps focus (Chakra `Drawer` does this).
- Status banners use `role="status"`.
- The skeleton grid has `aria-busy="true"` and visually hidden text "Loading articles".
